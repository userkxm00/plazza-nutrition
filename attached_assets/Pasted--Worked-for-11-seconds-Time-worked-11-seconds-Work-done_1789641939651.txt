Improve the existing Plazza Nutrition React/Vite app in place. Read the current source before editing; do not hand-code an approximation. This is a focused design iteration, not a new app and not a generic dashboard rewrite.

## Current component comprehension
- The app is a bilingual storefront plus operations workspace with a shared top-level lang/mode state.
- The current language toggle changes direction and only a small amount of copy; most customer and operations content remains French. This is the main gap.
- Operations is routed under /ops/:rest* with a sidebar and dashboard modules.
- POS is /ops/pos and currently shows fixture product search, an empty draft cart, an online-first visual signal, and an indicative total.
- All data is explicitly local fixture data and must stay non-authoritative.

## Hard constraints
- Preserve the product contract and existing route coverage.
- Do not invent real products, claims, reviews, delivery rates, courier capabilities, production persistence, or API behavior.
- Keep the fixture boundary visible and honest.
- Do not remove the French path; Arabic must become equally complete.
- Preserve responsive/mobile behavior, visible focus, accessible labels, reduced motion, and stable data-testid attributes.
- Do not use emojis anywhere in the UI.
- Keep styles centralized in artifacts/plazza-nutrition/src/index.css and keep service/fixture boundaries in artifacts/plazza-nutrition/src/lib/mock-service.ts.

## Design exploration brief
Function: help customers browse and buy, and help staff operate orders, stock, cash, and delivery quickly.
Content: customer storefront copy, product/category/search language, cart/checkout/order language, operations navigation and modules, statuses, POS controls and cash/session labels.
Interaction: language switch, direction switch, mode switch, route navigation, filtering, cart actions, checkout validation, POS search and local draft actions.
Visual structure: premium editorial storefront; dense operational shell; task-focused POS.

Variation axes selected:
1. Semantic completeness: move from French-first + partial Arabic to a real FR/AR copy dictionary used by shared shell, storefront, checkout, account, and operations.
2. Structural hierarchy: make operations answer attention/workflow/status questions at a glance, with clearer navigation groups, role/session context, search and action hierarchy without adding undocumented business modules.
3. Behavioral efficiency: make POS feel like a global retail workstation with persistent cart/total, clear cash-session and connectivity state, barcode/search affordance, keyboard shortcut hints, touch-friendly actions, and explicit draft/not-committed wording.

## Implementation goals
1. Add a typed lightweight translation layer in the frontend (no dependency required). The current active language should drive visible labels, headings, actions, status names, nav groups, empty/error/success copy, and key fixture notices. Include natural professional Arabic, not machine-like filler. Set document direction and language semantics correctly. Persist the preference locally if straightforward.
2. Translate the customer shell and primary routes: home, shop, search/categories, product detail, cart, checkout, confirmation, account/orders, delivery/help/policies, including buttons, labels, filter controls, and empty states. Keep product fixture content marked as visual fixture.
3. Translate operations navigation and dashboard/POS content. Keep role labels and fixture boundary visible. Improve operations visual hierarchy for scanability and international usability: clearer selected state, section grouping, top utility bar, command/search affordance, date/session/context line, status legend or labels, and a calmer dense grid. Avoid adding fake KPI values beyond existing fixture values.
4. Improve /ops/pos specifically: make product search/filter and cart/payment areas feel like a reliable checkout workstation, add clear session status and online-first/offline draft distinction, add shortcut hints as text, provide useful empty and local-action states, and keep it fast on tablet/mobile. Do not claim a sale committed.
5. Strengthen global polish where it matters: language button clarity, RTL icon/layout behavior, table alignment, logical CSS properties, focus rings, and mobile navigation labels.
